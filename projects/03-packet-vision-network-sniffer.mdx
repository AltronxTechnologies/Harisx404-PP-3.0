why_built: |
  Most educational or basic Python packet sniffers fail as soon as they encounter live network load. They run packet sniffing, parsing, and console printing in a single synchronous loop. When the console lags or buffers output, the sniffer drops packets on the socket buffer. Furthermore, standard Scapy usage defaults to storing all captured packets in memory, quickly leading to heap exhaustion and kernel crashes during sustained traffic.

  I built PacketVision to demonstrate how systems-level network programming principles can transform Python and Scapy into a robust, forensic-grade packet analysis utility. By decoupling ingestion from rendering via a bounded thread-safe queue and enforcing memory caps, PacketVision runs continuously under heavy traffic without dropping packets or leaking RAM.
key_decisions: |
  1. Producer-Consumer Architecture: Decoupled the packet receiver (Producer thread interacting with raw sockets via Scapy) from the packet analyzer and UI renderer (Consumer thread) using Python's synchronized `queue.Queue`.
  2. Bounded Queue & Memory Caps: Configured `store=False` in Scapy to avoid accumulating packet objects in the Python heap. Capped the inter-thread queue with a bounded sliding window, dropping the oldest non-critical packets gracefully if terminal rendering is artificially throttled.
  3. ANSI Escape Code Sanitization: Raw packet payloads can contain malicious byte sequences (e.g., ANSI cursor repositioning codes or terminal color resets) crafted by attackers to obfuscate activity or manipulate the analyst's terminal. Implemented strict printable-ASCII character filtering on all inspected payload strings.
  4. Multi-Platform Hardware Capture: Architected the socket layer to support native Linux raw sockets as well as Windows Npcap promiscuous mode drivers, with automated interface discovery and status verification.

## Executive Overview

**PacketVision** is a terminal-based network packet inspection and protocol telemetry utility designed and developed by **Muhammad Haris**. Engineered specifically to solve the performance and stability bottlenecks common in script-based packet analyzers, it employs a decoupled multithreaded architecture that protects system memory, sanitizes untrusted payload bytes, and delivers deep protocol visibility directly to the terminal.

It provides network engineers, penetration testers, and forensic investigators with immediate insight into raw wire communications without the heavy overhead of GUI applications.

## Deep Protocol Dissection Capabilities

PacketVision inspects packets across the full OSI transport and network stack:

* **Layer 2 (Data Link)**: Ethernet frame types, ARP hardware/protocol addressing, opcode decoding (Request vs. Reply).
* **Layer 3 (Network)**: IPv4/IPv6 source and destination addresses, TTL values, IP options, and CIDR subnet matching.
* **Layer 4 (Transport)**:
  * **TCP**: Source/destination ports, sequence and acknowledgment numbers, full flag matrix inspection (`[SYN, ACK, FIN, RST, PSH, URG]`), window sizing.
  * **UDP**: Port routing, datagram length, and checksum validation.
  * **ICMP**: Type and code classification (Echo Request/Reply, Destination Unreachable, Time Exceeded).
* **Layer 7 (Application Insights)**: DNS queries and transaction IDs, HTTP method inspection, TLS Client Hello SNI string extraction.

## Defensive Engineering: Anti-Terminal Injection

A critical security vulnerability in naïve packet sniffers is **Terminal Injection**. If an attacker broadcasts packets containing ANSI escape sequences (e.g., `\x1b[2J` to clear screen or `\x1b[?25l` to hide cursor), the terminal display can be blinded or spoofed.

PacketVision implements strict payload sanitization before any terminal emission:
```python
def sanitize_payload(payload_bytes: bytes) -> str:
    """Strips non-printable ASCII and escape sequences from untrusted payloads."""
    return "".join(
        chr(b) if 32 <= b <= 126 else "."
        for b in payload_bytes
    )
```

## Forensic Artifact Exports

Captured traffic can be exported in real-time or at session termination:
1. **Wireshark PCAP**: Native binary PCAP format compatible with Wireshark, Zeek, and Snort for downstream analysis.
2. **Structured JSON**: Detailed nested JSON object trees capturing exact packet timestamps, layer attributes, and hex dumps.
3. **Tabular CSV**: Flat time-series metrics optimized for Pandas dataframes and statistical traffic anomaly modeling.

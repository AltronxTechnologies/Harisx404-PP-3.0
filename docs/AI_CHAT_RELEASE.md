# Public portfolio assistant: Groq primary, Gemini fallback

## Implementation

- `app/api/ai/chat/route.ts` validates and rate-limits the existing bounded chat request, builds context from public settings, published projects and posts, then calls Groq's documented `https://api.groq.com/openai/v1/chat/completions` endpoint with a server-only key and a system instruction. The default is Groq's documented production model `openai/gpt-oss-20b`; `GROQ_MODEL` can override it after an owner-tested rollout. No new SDK dependency was added.
- Groq has an 8-second request deadline. Missing credentials, network errors, non-2xx responses, malformed JSON and empty answers fall through once to the existing Gemini chat model. An explicit Groq safety refusal does not fall through. Gemini is bounded to 10 seconds at the route level, although its current SDK call cannot be cancelled after that deadline; check usage at the provider. If neither gives a usable answer, return a safe HTTP 503 rather than a fabricated success. The browser is not told which provider answered; keys and raw provider errors stay on the server.
- The widget keeps the site's light/dark neutrals, Instrument Serif heading, monospace overline and purple accent without editing locked global styles. Its fixed card fits a narrow viewport or short height; content scrolls inside while the composer stays reachable. Suggestions, new chat, retry, plain-text answers with allowlisted local route links, status/error announcements, bounded input, Enter/Shift+Enter and Escape/focus return are implemented. Touch opening does not deliberately focus the soft keyboard. No conversation is persisted to storage or a database.

## Configuration

Set `GROQ_API_KEY` and `GOOGLE_AI_API_KEY` (or the existing `GEMINI_API_KEY` alias) privately in the hosting environment. The Alloy Compose service passes these variables through explicitly, but a running container needs an environment refresh after a new sandbox key is supplied. Do not put actual keys in `.env.example`, commits, screenshots, public `NEXT_PUBLIC_` variables or chat messages. `GROQ_MODEL` is optional and defaults to `openai/gpt-oss-20b`.

## Validation and limits

- `tests/chat-provider-fallback.test.mjs` exercises primary success, HTTP/network/malformed/empty failures, missing key, total outage and safety refusal with mock providers. `tests/public-auth-ai-boundaries.test.mjs` retains input and server-rendered markup checks.
- Browser preview checks covered a real 503 with a recoverable Retry state, then browser-only mocked success and an allowlisted internal link, Enter/Shift+Enter, new conversation and Escape focus return. Measured light 320x640 panel bounds were x=12..308 and y=24..560, with zero document overflow; 375x667 and short 768x500 also kept the composer visible. Dark 390x844 and light 1024x768 screenshots were inspected. These checks do not prove every physical device or screen reader.
- During local validation `GROQ_API_KEY` was absent, so no real Groq request was made. The configured Gemini key was present but the provider returned HTTP 403 in a status-only diagnostic; its contents and credentials were not printed. A live success or failover cannot be claimed until the owner supplies valid keys, enables the chosen model and completes a staging test. The previous project-wide production-readiness blockers in `docs/production-readiness-2026-10-09.md` remain open; this chat work is not production deployment approval.
- Docker verification: the focused provider/boundary suite passed 9/9, the SEO integration suite passed 4/4, and Contact/navigation/Home-About integration passed 11/11. `npx tsc --noEmit`, `npm run lint`, `git diff --check`, and the isolated `NEXT_DIST_DIR=.next-build npm run build` passed (83 generated pages; existing Edge/static and cache notices). The final build estimated 200 kB Home first-load JS and 103 kB shared; this is not a measured field performance gain. An initial combined parallel Node suite timed out after reporting 16 passing cases; it was rerun successfully as smaller suites. The dangling test-only processes were stopped without stopping the Docker web service.

## Hydration follow-up

On a later clean worktree, a fresh Playwright navigation to `/` reproduced a React hydration attribute warning for `ChatbotWidget`: the server document still emitted `z-[4000]` and no `type`/`aria-expanded`/`aria-controls` on Toggle chat, while the current mounted client source has `z-[5500]` and those attributes. `docker compose ... exec web node -e 'fetch(...)'` independently confirmed that the running dev server served the older markup, despite current source containing the new version. This was a dev-server server/client compilation skew after hot updates, not a `Date.now()` branch in ChatbotWidget. No markup suppression or change to the approved public design was used.

- PR-10 / confirmed dev-runtime defect / P2: expected a fresh document and client bundle to render the same ChatbotWidget attributes; actual stale server HTML caused a warning on every new Home document until the Docker dev service was refreshed. Added `tests/public-auth-ai-boundaries.test.mjs` coverage asserting the **served HTML** contains the current chat attributes. It failed against the stale service (3 pass, 1 fail); `docker compose -f docker-compose.alloy.yaml restart web` refreshed the process without changing Compose networking or taking the final stack down. The same suite then passed 4/4; fresh Playwright document navigations to `/contact?hydration-check=1` and `/` showed no hydration warning. A separate production build had already compiled successfully; production deployment hydration remains unverified. If this recurs after future hot edits, first compare the served HTML with the source and refresh the dev server rather than hiding React warnings.

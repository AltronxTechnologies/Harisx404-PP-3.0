## Findings And Tasks

**CT-01 - Confirmed validation focus defect, P2, locked form.** Empty submission announces four described invalid fields, but focus remains on the page body instead of the first invalid input after errors render, despite `setTimeout` plus `querySelector('[aria-invalid=true]')?.focus()` in `ContactClient.tsx`. **Task:** obtain a scoped owner unlock, diagnose the Next server-action/re-render timing, restore focus to the first invalid field after the error state commits without opening a mobile keyboard on initial page load; verify pointer/keyboard/touch submit, multiple invalid fields, correction/retry and focus-not-obscured. Roll back the focus-only amendment if normal form flow regresses. **Status: CONFIRMED, NOT CHANGED (locked).**

**CT-02 - Confirmed enlarged-text clipping, P2, locked Contact presentation.** At 390px with 200% root text, the 298px form grid grows an intrinsic 353px track; availability and form frames end at x=399, beyond viewport, hidden by ancestor clipping. **Task:** seek separate scoped permission to make Contact-only grid/field content shrink or wrap without changing the approved normal layout; test 320/375/390 in both themes, 200%/400% actual zoom, field errors/dropdown/CTA and physical touch. Do not mask overflow. **Status: CONFIRMED, NOT CHANGED (locked).**

**CT-03 - Deployed host and delivery blocker, P1.** Configured HTTPS `/contact` returns 404. Valid inquiry persistence/deduplication, rate limit, SMTP delivery, failed-send queue/retry and recovery cannot be certified without an approved safe recipient and restore-tested DB. **Task:** owner confirms actual deployed host and supplies a disposable SMTP inbox/database clone, effective RPC/grant inventory, rollback and consent; send one synthetic valid inquiry there, verify duplicate request-id, rate bound, success/failure messages, private storage and safe cleanup. Never send tests to a real visitor or mutate production data without approval. **Status: BLOCKED.**

**CT-04 - Owner claims, accessibility and field performance gate, P1/P2.** Response-time/privacy copy needs owner/legal accuracy approval. Full manual/automated WCAG and physical-device testing, controlled production-mode performance and deployed p75 Web Vitals remain unverified. **Task:** close those gates against confirmed staging after CT-01/02 are fixed; preserve locked design. **Status: BLOCKED.**

**Final verdict:** Contact renders and safely rejects invalid input locally, but it is **NOT READY FOR DEPLOYMENT** while error focus, enlarged-text clipping, the 404 host and real delivery/owner/manual release gates remain. No locked page or message data was changed.

**ABOUT-01 - Confirmed metadata mismatch, P2 discoverability defect, locked change requires approval.** `app/about/page.tsx:28-32` defines an About-specific title/description, but rendered local `/about` inherits generic OG/Twitter title and description from `app/layout.tsx:68-122`. Actual `og:title` and `twitter:title`: `harisx404 | Portfolio`; browser title: `About | harisx404`. Actual social description begins `I'm Haris, a Full-Stack developer & cybersecurity enthusiast.`; About description begins `Muhammad Haris — full-stack engineer...`. Expected social shares to describe the About route accurately, without inventing claims or changing visible presentation. **Plan A-01:** after a named About metadata unlock, add page-specific OG/Twitter title and description to `app/about/page.tsx` using the existing factual description and approved branding. Preserve the existing OG image, Twitter card, canonical, other inherited metadata and noindex policy; Next metadata nested objects can replace rather than merge parent fields. Test rendered local head, social asset, other routes' metadata and deployed preview; require owner copy approval before release. Risk: losing inherited social image or changing another route; rollback only scoped metadata fields. **Status: CONFIRMED, NOT IMPLEMENTED pending owner lock permission and target-host verification.**

**ABOUT-02 - Confirmed source behavior with unverified connected impact, P2 data-state risk.** `app/lib/utils.ts:423-434,479-480` returns `[]` for empty or failed published Experience reads; `app/components/Resume.tsx:282-290` then displays four static entries whenever the supplied array is empty. Therefore an owner intentionally unpublishing every Experience would still leave those entries visible, and a database outage cannot be distinguished from an intentional empty list. Current preview has four entries; **no** unpublish or outage was performed. Expected behavior for an empty Admin collection vs a transient outage requires owner decision because the fallback is a frozen About data-state contract. **Plan A-02:** on a separately restored disposable target, test last-entry unpublish and failed-read branches; agree whether empty means hide/empty message while failure should show approved cached content/error. Obtain a named About/Resume/data-state unlock before any change, preserve approved layout and use a reviewed cache/error strategy. Test owner save/reopen, published-only read, 60-minute cache invalidation, empty/error/recovery and responsive modes; rollback the scoped change if legitimate legacy fallback is lost. **Status: INVESTIGATION BLOCKED pending owner decision and safe connected target.**

**ABOUT-03 - Blocked factual/editorial approval, P1 release gate, not a claim of false credentials.** Local hero and Education copy (`app/about/page.tsx:68-75,128-146,171-185`) assert BSIT completion, 3.5/4.0 CGPA, Pakistan NSCT Top 15% in 2026, 96% coursework and KPITB training/certification; Experience rows assert specific roles and dates.

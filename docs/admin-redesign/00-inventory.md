# Admin Redesign Inventory

Status legend: **source-confirmed** = present in the current worktree; **observed** = supplied HTTP/read-only/browser evidence; **unverified** = not exercised with owner authentication; **blocked** = requires owner access/approval or a safe environment. This is a planning snapshot, not a production sign-off. See `06-validation-log.md` for evidence limits.

## Application map

- **Source-confirmed:** `package.json` uses Next 15 (`^15.5.26`), React and Tailwind. `app/layout.tsx` wraps all routes with public Navbar, side rails, Footer, theme provider and chatbot. `app/admin/layout.tsx` now adds Admin metadata (`noindex, nofollow`) but returns children unchanged; it does not isolate public chrome.
- **Confirmed in source, unverified in authenticated browser:** `app/admin/(dashboard)/layout.tsx` checks `getUser()` and normalized `ADMIN_EMAIL`, redirects anonymous users to `/admin/login` and non-admin users to `/`, then renders `Sidebar` plus a content grid. It uses local `#F6F7F9`/`#10131A` surfaces. `middleware.ts` also redirects protected `/admin*` routes, except `/admin/login`; middleware is not the API authorization boundary.
- **Confirmed in source:** `app/components/admin/Sidebar.tsx` has desktop fixed rail and mobile dialog drawer with Escape/Tab handling, background inertness and sign out. Destinations: Dashboard, Analytics, Blogs, Projects, Resume, Changelogs, Buildlog, Community Wall, Testimonials, FAQs, Experience, Certifications, Media, About, System Logs, Settings.
- **Source-confirmed, authenticated UI unverified:** `/admin` shows six stat cards (blog total/live/draft, projects, article views, reactions), quick actions and recent blog/project lists. Dashboard and Projects list call `requireAdmin()` before creating the server-only service-role client. Query errors show an unavailable dash or error row, not zero/empty; successful null counts can still fall back to zero. Draft visibility and values have not been owner-authenticated.
- **Source-confirmed; anonymous redirect observed:** `app/admin/(dashboard)/{media,about,settings}/page.tsx` now receives the Sidebar/content wrapper at unchanged URLs. Anonymous visits return 307 to `/admin/login`. `/admin/login` remains outside `(dashboard)`; all Admin routes still inherit public root Navbar/Footer/chat. The authenticated shell is unverified.

## Read-only and source observations (current worktree)

- **Observed current login:** `tests/admin-login.browser.test.mjs` passed 1/1 across 320/375/390/640/768/1024/1440 in light/dark: no overflow, one `h1`, labelled email/password fields at least 44px high, submit at least 48px, card fits, and robots noindex. This supersedes the old missing-`h1` and untested seven-width notes; it does not exercise form submission, error handling or owner login. Authenticated dashboard/editors remain **blocked**.
- **Observed connected read-only:** `site_settings` GET 200, one row with columns `id`, `site_name`, `seo_description`, `seo_keywords`, `github_url`, `twitter_url`, `linkedin_url`, `email_address`, `created_at`, `updated_at`, `show_faq_section`. Values are not recorded. Settings API now uses named columns, verified Admin then service role, strict optional Zod inputs and private no-store success responses; anonymous GET is now 401 (formerly 500). No save was exercised.
- **Observed anonymous GET (status only):** `/api/admin/about`, `/faqs`, `/changelogs`, `/media`, `/settings` now return 401; `/experience` previously returned 200 and has no new verification here. `/testimonials`, `/resume`, `/buildlog`, `/community-wall` previously returned 401; Blog/Projects GET previously returned 405. Neither prior 200 nor current 401 establishes what data was exposed or whether other methods are secure.
- **Observed connected read-only:** REST `select=id&limit=0` returned 200 for each of `about_content`, `about_sections`, `changelogs`, `changelog_entries`, `faqs`. A read-only column check found `about_content`: `id`, `hero_title`, `hero_subtitle`, section 1-4 `title`/`content`/`image_url`, `created_at`, `updated_at`; no values recorded. `system_logs?select=id,resolved&limit=0` returned 400 / `42703` (missing `resolved`).

## Findings, Ordered By Risk

**AI-01 / P1 / actual failover unavailable:** The configured Gemini model/key returned HTTP 404 here. Mocked failover tests show control flow, not an operational second provider; Groq failure may yield an SSE `UNAVAILABLE` error. Owner must select a supported model/account, rotate/configure valid credentials privately and demonstrate Groq-failure-to-Gemini success through the **confirmed** staging host. Do not publish or log keys. No model or credential was guessed or changed.

**AI-02 / P1 / rate limit is not a production-wide abuse bound:** `app/lib/rate-limit.ts` stores counters in an in-process `Map`; serverless instances/regions do not share it. `app/api/ai/chat/route.ts` also trusts `x-real-ip` before `x-vercel-ip` and finally the first `x-forwarded-for` value; whether a production edge overwrites those incoming headers has not been demonstrated. Source/mock tests are not a spoofing or distributed-load proof. Gate release on a trusted ingress identity and distributed rate/cost limit, with approved load/abuse checks on staging. Do not treat Web Analytics as a rate limiter.

**AI-03 / P1 / Gemini streaming is not end-to-end time-bounded:** The 4.5s race surrounds `sendMessageStream()` returning its iterator, but the following `for await (const chunk of streamResult.stream)` has no deadline or cancellation. Once started, a stalled fallback stream can exceed a serverless function budget, contrary to the runbook's claimed `<=9s` guarantee. Add a single end-to-end deadline, cancel/return the iterator where supported, and test stalled-provider and client-abort cases under a measured staging timeout before signing off. Neither the mock happy path nor a successful Groq call closes this.

**AI-04 / P1 / configured deployment is unreachable:** `https://harisx404.vercel.app/` returned 404. Confirm the actual project, branch mapping and primary HTTPS host, then smoke widget, API, proxies, CSP, streaming/no-buffering, disabled-mode behavior and rollback through that host. A local Docker build or pushed branch is not a deployed PASS.

**AI-05 / P1 / privileged project-read boundary corrected locally:** Previously chat imported `fetchProjects()` from `app/lib/utils.ts`. That helper switches to `SUPABASE_SERVICE_ROLE_KEY` server-side, bypassing anonymous RLS even though the chat route itself contained no direct service-key reference. It selected published rows, but the claimed public-client-only isolation was false, and the service role was unnecessary for the answer fields. Chat now reads only `title, slug, tagline, description, tech_stack, project_stage` from `projects` through `getPublicSupabase()`, filters to `status=published`, and omits project context if the public read fails rather than inventing a featured list. A source regression prevents the privileged helper returning. This fix is locally checked; public-view/RLS behavior on the actual production target remains a release gate.

**AI-06 / P2 / grounding and claims need owner verification:** The system prompt hard-codes education/honor/certification assertions and `buildSiteContext()` keeps a 10-minute in-memory copy. An LLM prompt alone cannot guarantee no hallucinations or perfect injection resistance. Review the public corpus and static assertions with the owner; test read failures and a redacted, approved evaluation on current content. The earlier pre-fix local live smoke may have used the service-role helper on published rows and must not be cited as anonymous-only proof.

**AI-07 / P2 / prior documentation overstated proof:** The older `final-production-readiness-audit.md` says READY, modal `aria-modal=true` with focus trap, immediate no-redeploy environment kill switches, global per-IP protection and a guaranteed timeout. Its illustrative 29-test transcript does not match the actual checked-in test names/output, and its metadata names an older revision while discussing later changes. Treat it as historical, not an acceptance certificate. The current widget has a non-modal dialog; `AI_ASSISTANT_DISABLED` blocks the API but does not unmount the launcher, and Vercel env changes need the host's deployment propagation verified. The non-streaming API returns `{text}`, not `{reply}`.

**AI-08 / locally corrected:** Previously a partial streamed answer followed by an SSE error left a model message last; Retry submitted that model text instead of the user's question, causing the actual API to reject the request as an invalid conversation. On a 320px first open the scroll-follow effect skipped the welcome heading, and X/Escape/launcher close did not abort pending generation. These are now scoped client fixes covered by `tests/ai-chat-checkup.browser.test.mjs`, not evidence that AI-01..04/06..07 are closed.

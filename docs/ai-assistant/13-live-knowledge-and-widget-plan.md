# Live Public Knowledge and Assistant Widget

**Status:** Implemented locally, not production-approved. Target deployment: `harisx404.vercel.app` after the owner deploys it. This change does not deploy or mutate any connected content.

## Architecture and Scope

1. The chat route calls `retrievePublicKnowledge()` for each valid question. Its anonymous Supabase client reads published projects and case-study fields, published and already-released full blog articles, the public credentials and Buildlog views, published experience and testimonials, visible FAQs when the section is enabled, public community-wall messages for wall questions, site settings, and public resume metadata. Versioned static homepage, About, contact and links facts provide navigation and stable identity facts. No Admin client, privileged service role, drafts, future posts, private submissions or unpublished wall messages enter the retrieval context.
2. Record paths are constructed from validated published slugs, rather than copied from user content. A bounded lexical ranker selects question-relevant excerpts (maximum five records / 12,000 context characters); the newest-blog question selects the first published article ordered by publication date. The prompt distinguishes untrusted excerpts from instructions and separates personal facts from general explanations. The API sends server-selected page metadata alongside the answer in both SSE and JSON responses. The widget renders allowed destinations as titled, clickable relevant-page chips; model-generated dynamic paths are clickable only when that destination appeared in the verified metadata. Source chips are related pages, not a claim that every sentence has a formal citation.
3. Fresh anonymous reads on every valid chat request mean that a later request observes an Admin publish, edit, unpublish or deletion on the database without depending on the previous process-local 10-minute chat cache. Static source changes still require a code deployment; the site's own ISR page cache can temporarily render older content than the chat's fresh database read. Query limits mean this is not unlimited site-wide semantic search: older records past the per-table limits and terms that lexical ranking cannot match need a designed search index if the collection grows.
4. The public Resume PDF is linked only when public metadata indicates an active document or the public fallback. **PDF text is not indexed**: uploaded bytes live in a private storage bucket and there is no existing public text-extraction contract. Full searchable PDF knowledge would require a scoped upload-time extraction pipeline, a public-only text representation synchronized on replace/disable/delete, a validated database migration and connected staging tests. Do not scrape private storage with a service key from the public chat endpoint.

## Interface Decisions

- The robot is a lightweight shaded SVG with a subtle perspective/idle animation and reduced-motion fallback. It is not a WebGL mesh. This avoids loading a 3D engine and GPU canvas on every portfolio page for a small floating launcher; a genuine interactive WebGL model remains a separate asset/performance decision.
- A quiet, dismissible prompt appears once per browser session after twelve seconds without interaction. No recurring notifications, auto-open, audio or unsolicited focus. The chat panel remains a non-modal dialog; outside pointer interaction closes it, and a swipe on its header (not the message scroller) can close it on touch devices. Escape, close and launcher still work, restore focus when appropriate and abort in-flight requests.
- The existing site type, surfaces and colors are retained. Markdown is rendered without raw HTML; links are restricted to known local pages and explicitly retrieved dynamic sources. Do not treat this as a screen-reader or physical-device certification.

## Validation and Release Gates

- Docker: `node --test --test-concurrency=1` over the chatbot suites passed **39/39**; `npx tsx --test tests/public-knowledge.test.ts` passed **7/7** including edit, unpublish, delete, newest publication, short-query ranking and private/draft exclusions. Lint, isolated `.next-build` build (84 pages), TypeScript and `git diff --check` passed. Browser cases cover 320px Markdown, robot launch, 375px touch swipe, outside click, JSON/SSE source chips, one-time prompt and reduced motion. A local live Groq request answered a SOC question using the published internship with a link to `/about`. This does not imply universal factual accuracy or a production SLA.
- Before deployment: verify actual Supabase public-view grants, collection sizes, latency, RLS and API costs on disposable connected staging; add a scalable retrieval/index strategy as content grows; design public PDF-text extraction if that coverage is required. Compare Admin publication and page ISR behavior with the chat after edit/unpublish/delete. Validate AI answers with an owner-approved redacted question set and real touch, keyboard and assistive technology.

# AI Assistant Pre-Deployment Checkup

**Scope:** local Docker app and Alloy preview, after the live-knowledge/widget changes. **Verdict: NOT READY for production sign-off.** No live Vercel deployment exists yet; "100% accuracy" and universal device/performance guarantees cannot be established from a local model sample.

## Verified Locally

- Reproduced and corrected clean Groq EOF after a partial delta being reported as success; the server now requires a provider completion marker. A late content-filter event is not treated as a successful response. The browser likewise requires an SSE `done` event and shows Retry for truncated answers. A short follow-up now carries the preceding user subject into retrieval, without mixing in old context for explicit latest-blog queries.
- Gemini fallback's 4.5-second deadline now covers the iterator as well as startup. A mocked stalled stream emitted a retryable error at approximately 4.5 seconds, not `done`; a canceled Groq stream aborts its fetch signal. This is a bounded local test, not proof that every SDK operation cancels or that serverless/network proxies meet the same bound.
- Anonymous public reads have a 3-second deadline. An explicit latest-blog question makes only **one** public article query (`limit 1`), rather than ten public-collection queries. Other questions still query multiple bounded collections and need load/latency testing before release.
- Sampled local retrieval (not an SLA, warm/cold and network conditions vary): before latest-blog specialization about **1057 ms**, with other queries about **771-1004 ms**; after specialization one observed latest-blog query about **826 ms**, other queries about **1249/1228 ms**. A single Docker-served live Groq SSE question about the latest post finished with a published `/blog/ai-security-operations-center` source in **1420 ms**. No p50/p95 under load, browser field data or deployed timings were measured.
- Docker chatbot protocol/security/browser suite: **44 passed, zero failed/skipped**; fresh public-knowledge suite: **7 passed, zero failed/skipped**, including publish/edit/unpublish/delete, draft/scheduled exclusion and a one-query latest-post budget. Docker lint, isolated `NEXT_DIST_DIR=.next-build npm run build` (84 pages), post-build TypeScript and `git diff --check` passed. Browser tests are mocked for failure states; one live Groq observation does not prove perfect grounding or live failover.

## Remaining Release Gates

1. **Distributed abuse and cost limits:** `app/lib/rate-limit.ts` is process-local, so 25/minute is not a deployment-wide bound. Verify trusted client identity at the Vercel edge, deploy a shared limiter or equivalent trusted edge control, then conduct authorized staging abuse/load tests. Do not call the current Map a production-wide protection.
2. **Live provider fallback:** the configured Gemini key/model previously returned HTTP 404. Fix configuration privately and verify a Groq-failure-to-Gemini success through staging, including stalled stream and cancel behavior. Do not print keys.
3. **Freshness and coverage:** full uploaded Resume PDF text is not indexed; only public metadata/link is available. Retrieval is lexical and capped per source; static facts update on deploy, and page ISR may temporarily display older content than fresh chat reads. Verify public-view grants and changed/deleted records on disposable connected staging without touching real content; plan an upload-time public-only PDF text contract if required.
4. **Deployment and accessibility:** `harisx404.vercel.app` has not been deployed yet. Verify real HTTP/SSE buffering, production CSP, rollback, rate control, error telemetry, field performance and owner-approved grounded-answer evaluation on that host. Check actual touch devices, keyboard and assistive technology in light/dark and reduced-motion modes. The robot is lightweight shaded SVG, not a WebGL 3D mesh; no pixel-perfect or WCAG certification is claimed.

**Boundary:** This checkup changes only chat API, retrieval, widget regressions and chatbot documentation. It does not deploy the site, alter providers, mutate live data or sign off unrelated owner-locked pages.

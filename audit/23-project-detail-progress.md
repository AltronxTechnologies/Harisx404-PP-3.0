# Project Detail: Verification In Progress

The detail template now reads published project fields and ordered gallery media from Supabase. It renders the Admin-authored Markdown narrative, optional highlights, one carousel containing the cover first and the additional images after it, metadata and structured data without generating generic project claims. The Admin form can choose, caption, reorder, replace and remove additional images. Fallback case studies are disabled in production; development fallback remains available when no published DB list is returned.

## Verified

- `npm run test:projects`: published index links resolve, missing content stays unindexable, unauthenticated mutations return 401, and the gallery/narrative plumbing remains connected.
- Container TypeScript (`npx tsc --noEmit`) and targeted ESLint pass.
- Browser checks at 320px, 390px and 1440px show no horizontal overflow. Light and dark themes render correctly. The share control opens with pointer/keyboard and Escape restores focus. Published `intrushield-nids` shows its project images and related project links.

## Owner-Managed Expansion

- Project type remains free-form for cards, filtering, and related work but is no longer repeated among the four left-hand facts: Built, Latest update, Visit, Source. The right panel splits comma- or spaced-slash-separated categories into individual pills alongside every Admin tag; `AI/ML` remains one category. A vertical rule separates the columns on desktop, and Tech stack remains in a full-width row beneath. Stage was removed before its migration was applied. Visit shows a blue link only when a URL exists, otherwise None. The existing `source_note` field is the source link name when a URL exists and the unavailable-source note when it does not; previously saved notes are preserved. The short card/page summary is capped at 160 characters in Admin and across public card/detail views.
- Tech stack entries are one per line with no project-level item cap; curated tools use the same simple-icons source as home cards, and unknown tools are displayed without a guessed icon. The media picker can load older images beyond the first 50.
- Profile-only GitHub URLs no longer claim to be project source; the Admin field now asks for a direct public repository URL.
- Optional Markdown fields for Why I built this, Key decisions, Results and What I learned complement the existing overview and Highlights (the concise key-features list). Sections are hidden when empty. Up to two related projects are selected by published tag/stack/specific-type overlap; if there are no trustworthy matches or the list cannot load, the page shows a Browse projects link instead of invented recommendations.
- The Share menu now offers Copy URL, View as Markdown, Open in ChatGPT, and Open in Claude. Opening Claude copies a prompt for pasting; ChatGPT receives a URL-based prompt. On small screens the menu expands inline below the button so it cannot cover the project title.
- **Database status update:** a subsequent read-only check found all columns from `migrations/2026_project_case_studies.sql` available in the connected Supabase project. The earlier missing-column (`42703`) observation is superseded. Authenticated Admin saves and gallery round trips are still untested; the Alloy-only preview seed in `audit/24-project-preview-seed.md` does not write to the database.
- Admin tags no longer have a project-level count cap. The Projects index receives all tags for search and filtering while its shared cards still display only three chips.
- Admin project images require a cover, followed by any number of optional additional images. The cover has Upload, Choose from library, Upload replacement, and Remove (when a next image can be promoted) actions plus a direct-URL option and live preview. Additional images can be uploaded, chosen, captioned, reordered, promoted to cover, replaced, or detached. Removing them does not delete shared media assets. The public carousel displays the cover first and the rest in order; the separate Gallery story section is gone. The image viewport is fixed at 16:9 at all breakpoints and uses `object-cover` for every orientation (cropping edges as needed). The image moves horizontally one slide at a time while the box stays put. A slightly tinted, fixed-height caption strip shows one centered, quoted 12px line at font weight 400, without a visible image number. Newly entered Admin captions are limited to 32 single-line characters; older persisted captions are preserved until edited and still visually truncated. The controls copy the homepage testimonial indicators, five-second colored fill and circular play/pause button, with matching-size previous and next buttons. A stopped slide retains a fully colored active indicator. On narrow screens the indicators have their own centered row above the three buttons; on desktop the controls share one row. Swipe and reduced-motion support remain.
- The media upload route requires a verified Admin user, accepts Cloudinary-supported non-SVG images without a hardcoded app-level file-size cap, and writes media through the service-role client (the authenticated client had no media INSERT policy). Cloudinary-hosted carousel images request width-aware `f_webp,q_auto:good,c_limit` variants; Next optimizes other approved image hosts. Arbitrary externally hosted manual URLs cannot be guaranteed WebP or remote-size optimized. Cloudinary plan limits, request-body limits and available memory still bound uploads. Alloy Compose passes the available Cloudinary credentials through to the container. An authenticated Admin upload and project save remain to be exercised before write-path sign-off.
- The full-screen image viewer and image click-to-expand behavior have been removed. The photo remains swipeable for carousel navigation; arrows, indicators and play/pause buttons remain keyboard operable. The carousel crossfades slides and respects reduced motion.
- Autoplay waits until at least 35% of the frame is visible and the tab is active, so the cover remains first while it is offscreen. Hovering the image or controls does not pause or restart the five-second progress timer; only explicit pause/play, visibility and slide changes affect it. While visible, the carousel prepares only the previous and next images for immediate crossfades; a farther uncached image retains the old slide and shows a loading label only after 350ms. The disposable preview still uses explicitly labelled stock reference images; no real owner project screenshots exist in the repository. Replace those through Admin when authentic assets are available rather than implying stock is shipped work.

## Not Locked

- Unknown slugs render the not-found content and `noindex`, but Next 15's streamed/prerendered response currently sends HTTP 200. Calling `notFound()` in metadata and forcing dynamic rendering did not change this. Fix and verify a real 404 before SEO/status sign-off.
- Project, gallery and tag writes are separate DB operations. `saveGallery` deletes all previous image rows before inserting replacements; failed inserts or concurrent saves can leave a partial project. A transaction/RPC and optimistic concurrency check are needed before write-path sign-off.
- Authenticated Admin gallery add/reorder/caption/remove has not been exercised against the connected database; no live owner records were mutated during this audit.
- Several published case studies remain sparse and use stock/irrelevant Unsplash imagery. Owner-authored narratives and real screenshots are needed for content approval. A project-list outage can still show checked-in fallback cards on the separately audited Projects index while production detail links return not found.
